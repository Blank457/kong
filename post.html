拆解 Linear 的滚动动画
从弹簧物理到帧预算

逐帧分析 Linear 如何在 60fps 内实现丝滑的列表动画，以及如何在 React 中复刻这套体验。

Lin Chen
2026·10·06 · 12 min read
动画 React 性能

如果你用过 Linear，大概率对它的列表动画有印象——拖拽排序时项目卡片丝滑地让位，滚动时元素优雅地淡入，整个界面几乎没有"跳"的瞬间。这种质感不是偶然，背后是一套精心设计的弹簧物理 + 帧预算方案。

这篇文章我会拆开 Linear 的动画实现，看它如何在每一帧 16.6ms 的预算内完成布局计算、样式更新和合成层提交，最后给出一个可在 React 中直接使用的复刻方案。

一、先看现象：它到底丝滑在哪

普通的列表重排动画通常是这样的：你拖动一个元素，其他元素用 transition: all 0.3s 让位。问题是 all 会触发非合成属性的动画，导致主线程阻塞，一拖动整个列表就开始掉帧。

Linear 的做法不同。它把每个卡片的位移拆成两层：

  • 布局层：用 FLIP 技术记录前后位置差，只做一次 transform
  • 视觉层：在 transform 之上叠加弹簧阻尼，让运动有"惯性感"

关键在于：两层都只操作 transform 和 opacity——这两个属性不会触发 layout 和 paint，直接在合成线程上完成，主线程完全释放。

合成层动画是 60fps 的前提。任何触发 layout（width/height/top/left）或 paint（background/color）的动画属性，都会把工作扔回主线程，在复杂列表里几乎必然掉帧。

二、FLIP：用 invert 思维消除布局跳变

FLIP 是 First, Last, Invert, Play 的缩写，由 Paul Lewis 提出。核心思路是：先记录元素的初始位置（First）和最终位置（Last），然后瞬间把元素"反转"回初始位置（Invert），最后播放动画到最终位置（Play）。

听起来绕，但代码很直接：

flip.ts 
function flip(el: HTMLElement, lastRect: DOMRect) {
  // First: 当前位置（已经是 Last 了，因为 DOM 已更新）
  const first = el.getBoundingClientRect();
  // Invert: 算出位移差，瞬间拉回原位
  const dx = lastRect.left - first.left;
  const dy = lastRect.top - first.top;

  el.style.transform = `translate(${dx}px, ${dy}px)`;
  el.style.transition = 'none';

  // Play: 下一帧解除 invert，让 transform 回到 0
  requestAnimationFrame(() => {
    el.style.transition = 'transform 0.4s cubic-bezier(0.16, 1, 0.3, 1)';
    el.style.transform = '';
  });
}

这里有个细节：缓动函数用的是 cubic-bezier(0.16, 1, 0.3, 1)，这是所谓的"ease-out-expo"——前半段快速启动，后半段极度平缓地停下。它比 ease-out 更"果断"，符合 Linear 那种干脆利落的运动语言。

三、弹簧物理：让"停下"有重量感

纯缓动曲线的问题是：它太"数学"了，运动到终点时没有物理上的重量感。Linear 在此之上叠加了一层弹簧阻尼。

弹簧动画的核心是求解阻尼振动方程。Framer Motion 把它封装成了 spring transition，但理解原理有助于调参：

spring.ts 
// 简化的弹簧步进：每帧根据当前位移和速度计算下一帧
function springStep(state: { x: number; v: number }, dt: number) {
  const stiffness = 150;  // 越大越"硬"
  const damping = 20;    // 越大越少震荡
  const mass = 1;

  const force = -stiffness * state.x - damping * state.v;
  const acceleration = force / mass;
  state.v += acceleration * dt;
  state.x += state.v * dt;
  return state;
}

stiffness: 150, damping: 20 是 Linear 风格的常用参数——足够硬，不会软绵绵地晃；但又不至于像 stiffness: 400 那样生硬。这种参数需要靠手感调，没有公式可循。

为什么不用 CSS transition + 弹簧缓动？

理论上可以用一条弹簧缓动曲线近似弹簧效果，但实际有两个问题：

  1. 无法中途打断。用户连续拖动时，动画需要不断重定向到新目标，CSS transition 做不到平滑接管，而 JS 弹簧可以每帧重置目标。
  2. 速度继承。放手那一刻，元素应该带着拖动速度继续运动，只有 JS 弹簧能读取并继承这个初速度。

"动画不是装饰，是连续性。当用户的手离开屏幕，动画要接管手留下的动量——这才是丝滑的本质。"

四、帧预算：16.6ms 里要花在哪

60fps 意味着每帧 16.6ms。一个列表如果有 50 个卡片，重排时每个都要做 FLIP 计算，很容易超预算。Linear 的优化策略：

  • 只动画可见项。视口外的卡片直接跳到最终位置，不做 FLIP。用 IntersectionObserver 判定可见性。
  • 批量读、批量写。先循环读完所有 getBoundingClientRect（强制 reflow 一次），再循环写 transform。避免读写交替触发多次 reflow。
  • will-change 提示。对即将动画的卡片提前设置 will-change: transform，让浏览器预创建合成层。动画结束后移除，避免内存占用。
batch-flip.ts 
// 批量读：一次性读完所有旧位置
const lastRects = new Map();
items.forEach(el => lastRects.set(el, el.getBoundingClientRect()));

// DOM 更新（重排发生在这里）
reorderDOM(items);

// 批量写：一次性算完所有 invert 并应用
const visible = items.filter(isInViewport);
visible.forEach(el => {
  const last = lastRects.get(el)!;
  flip(el, last);  // 只写 transform，不触发 reflow
});

实测在 50 项列表里，这套方案的单帧耗时稳定在 3-5ms，留出充足余量给合成层渲染。

五、在 React 中复刻

React 的难点是：状态更新和 DOM 更新之间有异步间隔，FLIP 的"瞬间 invert"需要精确在 DOM 更新后那一帧执行。解法是用 useLayoutEffect——它在 DOM 更新后、浏览器绘制前同步执行，正好是 FLIP 的窗口期。

useFlip.tsx 
function useFlip<T>(deps: T[]) {
  const refs = useRef(new Map());
  const [rects, setRects] = useState(<DOMRect>[]);

  useLayoutEffect(() => {
    const next = [...refs.current.values()]
      .map(el => el.getBoundingClientRect());
    setRects(next);
  }, deps);

  return { refs, rects };
}

实际项目里我更推荐直接用 framer-motion 的 <Reorder> 组件，它已经把上面这些细节封装好了。但理解原理，你才知道遇到性能问题时该调哪个旋钮。

总结

Linear 的滚动动画之所以丝滑，可以归结为三件事：

  1. 只动合成属性——transform 和 opacity，把动画移出主线程
  2. FLIP 消除跳变——用 invert 思维让重排看起来是连续的
  3. 弹簧叠加物理感——在缓动之上加阻尼振动，让运动有重量

这三条都不复杂，难的是把它们在 16.6ms 的预算里组合起来。当你下次看到一个"丝滑"的界面，不妨用 Performance 面板看看——大概率合成层上跑着 transform，主线程几乎闲着。
